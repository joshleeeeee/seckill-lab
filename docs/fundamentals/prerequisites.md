# 前置知识快读（15-30 分钟）

这份文档不是系统课，而是帮助你快速补齐学习秒杀系统的最低知识门槛。

> 如果你只想先跑通实验，可用 Docker 启动中间件（MySQL/Redis/RabbitMQ），应用在 IDEA 中启动，便于边跑边调试。

## 你至少要会什么

| 主题 | 最低要求 | 不会会卡在哪 | 建议补齐方式 |
|---|---|---|---|
| Java | 能读懂类、方法、集合、异常 | 看不懂服务层与并发代码 | 跟着章节边看边查 |
| HTTP/REST | 知道 GET/POST、JSON 请求响应 | 不知道接口在做什么 | 先跑 curl，再看返回 |
| SQL/MySQL | 会基本 `SELECT/INSERT/UPDATE` | 看不懂 v1 唯一约束和乐观锁 | 跟着 migration 文件学 |
| Redis | 知道 key/value 和过期 | 看不懂 v2 库存预热与 Lua | 先理解原子扣减再看脚本 |
| MQ | 知道生产者/消费者模型 | 看不懂 v3 削峰与异步下单 | 先看队列积压与延迟指标 |

## 5 分钟术语预热

- 并发：同一时间段内有很多请求同时处理。
- 竞态条件：结果取决于执行先后顺序，顺序不同结果不同。
- 原子性：一个操作要么全成功，要么全失败，不能中间态。
- 幂等：同一个请求执行多次，结果应该一样。
- 最终一致性：短时间允许不一致，但最终要对齐。

如果这些术语还不熟，先看：`core-concepts.md`。

## 学习前自测（通过 4/6 即可开始）

1. 你能解释为什么“先查库存再扣库存”会有并发风险吗？
2. 你知道什么是唯一索引吗？
3. 你能看懂一条 `curl -X POST ...` 命令并执行吗？
4. 你知道 Redis 和 MySQL 在系统中的职责通常不同吗？
5. 你知道消息队列是用来“削峰”和“解耦”的吗？
6. 你知道“重试”为什么可能产生重复下单吗？

## 不会怎么办（快速补齐策略）

- 不要停下来系统补课，先继续章节。
- 遇到不懂概念，回到概念文档按关键词查。
- 每章只补当前必需的 1-2 个点。
- 先保证“能跑通实验”，再追求“深入理解”。
