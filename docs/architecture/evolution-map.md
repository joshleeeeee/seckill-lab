# 演进路线图

本文档不仅是架构路线图，也是教学路线图：每个阶段都对应一个要复现/解决的问题、一个关键机制，以及一个可验证的学习产出。

## 当前阶段：v2（v0/v1 作为对照基线保留）

- 部署形态：单个 Spring Boot 应用
- 下单流程：同步请求 -> Redis Lua 原子扣减 -> MySQL 订单落库
- 保障能力：Redis 热点库存削峰 + DB 唯一约束兜底
- 当前瓶颈：订单写库仍是同步链路，峰值时延会抬升

## 分阶段教学计划

| 阶段 | 核心问题或目标 | 关键机制 | 需要讨论的取舍 | 学习产出 |
|---|---|---|---|---|
| v0 | 复现超卖与重复下单 | 不安全的两步扣减 | 简单实现 vs 正确性 | 故障证据 + 根因说明 |
| v1 | 建立 DB 正确性基线 | 唯一约束 + 乐观锁 | 高并发下 DB 争用 | 约束设计 + 前后对比指标 |
| v2 | 保护库存热点路径 | Redis 预热 + Lua 原子扣减 | 与 DB 的最终一致性 | Lua 脚本 + 对账说明 |
| v3 | 扛住瞬时流量峰值 | MQ 异步下单 | 排队延迟 vs 用户体验 | 队列堆积和延迟分析 |
| v4 | 重试下保持正确 | 请求幂等 + 消费去重 | 幂等存储成本 | 幂等键与去重策略 |
| v5 | 局部失败后可恢复 | 超时关单 + 回补补偿 | 补偿链路复杂度 | 恢复场景验证记录 |
| v6 | 降低恶意流量影响 | 动态路径 + 验证码 + 限流 | 风控误杀率 | 风控规则与误杀分析 |
| v7 | 提升线上可观测性 | 指标 + 链路追踪 + 看板 | 埋点成本 | 监控看板与告警基线 |
| v8 | 提升可扩展性 | 可选服务拆分 | 运维复杂度上升 | 拆分方案与迁移清单 |

## 如何使用这份路线图

1. 不要跳阶段，每一阶段都在解决一类典型问题。
2. 每阶段都写一份简短记录：问题 -> 方案 -> 指标变化。
3. 用同一套压测方式贯穿全流程，保证对比公平。
